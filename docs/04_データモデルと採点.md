# 04. データモデルと採点方式

本アプリの核。**「断面図を描く」という作業をどうデータ化し、どう採点するか**を定義する。

---

## 1. 基本方針：セルベース作図

教科書の断面図問題は**方眼紙**の上で出題される。この性質を利用し、
「自由に線を引く」のではなく **「方眼のセルを塗る」** という操作に置き換える。

| | 自由線描画方式 | **セル塗り方式（採用）** | 選択式 |
|---|---|---|---|
| 操作の易しさ | △ 端点スナップ等が必要 | ◎ クリック／ドラッグのみ | ◎ |
| 採点の確実性 | △ 線の分割・順序で表現がぶれる | ◎ 集合の比較に還元できる | ◎ |
| 学習効果 | ◎ | ○ 形状とルールの理解は問える | △ 作図力は身につかない |
| 表現力 | ◎ 任意形状 | △ 45° 斜面まで（三角セルで対応） | – |
| 実装コスト | 大 | **中** | 小 |

**採用理由**: 断面図の学習目標は「切り口の形が分かること」と「どこにハッチングするか判断できること」であり、
線を美しく引く技能ではない。セル塗り方式はその 2 点を過不足なく問える。

### 45° 斜面への対応（三角セル）

方眼問題では斜面はほぼ 45°（対角線）である。そこで、1 セルの状態を次の 6 種で表す。

| 記号 | 意味 | 図 |
|---|---|---|
| `-` | 空（材料なし） | `□` |
| `F` | 全塗り（Full） | `■` |
| `BL` | 左下三角（Bottom-Left） | `◣` |
| `BR` | 右下三角（Bottom-Right） | `◢` |
| `TR` | 右上三角（Top-Right） | `◥` |
| `TL` | 左上三角（Top-Left） | `◤` |

これで、参考問題 (a) のリブの斜面のような形状も表現できる。

## 2. 座標系

```
      col →  0    1    2    3
          ┌────┬────┬────┬────┐
row  0    │    │    │    │    │      セル座標 (col, row)   : 0 ≦ col < cols, 0 ≦ row < rows
 ↓        ├────┼────┼────┼────┤      格子点座標 (x, y)     : 0 ≦ x ≦ cols, 0 ≦ y ≦ rows
     1    │    │(2,1)    │    │
          ├────┼────┼────┼────┤      原点は左上。row は下向きが正（SVG と同じ向き）
     2    │    │    │    │    │
          └────┴────┴────┴────┘
```

- **セル**: 塗りつぶしの単位。`[col, row]`
- **格子点**: 線分の端点。`[x, y]`（中心線・切断線など、出題側が与える線に使う）
- 1 セルの画面上のサイズ（ピッチ）は `grid.pitch`（px）。既定 28px
- 線分の座標は原則整数だが、中心線のように格子の中間を通る線のために**小数を許容**する（例 `[0, 5.5]`）

```jsonc
  "id": "sec-a-001",
  "title": "全断面図 A-A",
  "category": "full",            // full | half | partial | revolved | offset
  "level": 2,
  "instruction": "(答)の箇所に指示された断面図をかきなさい。ハッチングもほどこしなさい。",

  // ── 出題側：与える投影図（読み取り専用で表示する） ──
  "views": [
    {
      "name": "正面図",
      "grid": { "cols": 10, "rows": 16, "pitch": 24 },
      "solid": [[0,0,"F"], [1,0,"F"]],          // 塗り（形状を面で与える場合）
      "lines": [                                 // 線で与える場合
        { "a": [0,0], "b": [10,0], "kind": "outline" },
        { "a": [5,-1], "b": [5,17], "kind": "cut" }

  // ── 解答欄 ──
  "answerArea": {
    "title": "A-A",
    "grid": { "cols": 6, "rows": 16, "pitch": 28 },
    "hintLines": [                               // 最初から引いておく線（中心線など）
      { "a": [0,8], "b": [6,8], "kind": "center" }
    ]
  },

  // ── 正解 ──
  "answer": {
    "solid": [ [0,0,"F"], [1,0,"F"] ],           // 切り口＋見え掛かりを含む「材料のある」セル
    "hatch": [ [0,0], [1,0] ],                   // そのうちハッチングを施すセル（solid の部分集合）
    "tolerance": {
      "solidJaccard": 0.92,                      // この一致度以上で「形状 正解」
      "hatchJaccard": 0.92
    }
  },

  // ── 採点のヒント：典型誤答の定義（フィードバック生成に使う） ──
  "traps": [
    {
      "tag": "rib-hatched",
      "cells": [[2,9],[2,10],[2,11],[2,12],[3,11],[3,12]],
      "when": "hatched",                         // hatched | filled | empty
      "message": "リブは長手方向に切断してもハッチングしません（JIS B 0001）。切り口の輪郭だけを描きます。",
      "penalty": 20
    },
    {
      "tag": "off-plane-hole",
      "cells": [[4,14],[5,14]],
      "when": "empty",                           // 塗るべきなのに空にしている
      "message": "切断線 A-A が通らない穴は、この断面には現れません。",
      "penalty": 10
    }
  ],

  "hints": [
    "切断線 A-A は部品の中心を通っています。",
    "リブは切断面に沿って切られていますが、ハッチングはしません。",
    "座ぐり穴は中心線上にないので断面には現れません。"
  ],
  "explain": "この断面図は…（解説本文）"
}
```

### 線種 `kind`

| 値 | 用途 | 描画 |
|---|---|---|
| `outline` | 外形線 | 太い実線 |
| `hidden` | かくれ線 | 破線（断面図では原則使わない） |
| `center` | 中心線 | 細い一点鎖線 |
| `cut` | 切断線 | 一点鎖線（両端・屈曲部を太く）＋ 矢印 |
| `dim` | 寸法・補助線 | 細い実線 |

## 4. 解答 JSON（生徒が提出するもの）

```jsonc
{
  "problemId": "sec-a-001",
  "schemaVersion": 1,
  "solid": [ [0,0,"F"], [1,0,"F"], [2,9,"BR"] ],
  "hatch": [ [0,0], [1,0] ],
  "meta": { "elapsedSec": 214, "hintUsed": 1, "undoCount": 7 }
}
```

- `solid` は**セル座標と形状**の組。`hatch` は**セル座標のみ**（`solid` に含まれるものだけ有効）
- 比較用に `"col,row"` 文字列をキーとした `Map` に正規化してから採点する

## 5. 採点アルゴリズム

### 5.1 全体の流れ

```
1. 正規化      : solid / hatch を Map<"c,r", shape> と Set<"c,r"> に変換
2. 形状スコア   : Jaccard 係数（三角セルは形状一致も見る）
3. ハッチスコア : Jaccard 係数
4. トラップ判定 : traps の各条件に当てはまるか判定 → 減点 ＋ フィードバック
5. 総合点      : score = clamp(0, 100, 60*形状 + 40*ハッチ − Σペナルティ)
6. 合否        : 形状・ハッチとも tolerance 以上 かつ トラップ非該当 → 合格
```

### 5.2 形状スコア

```javascript
// A: 正解の solid, B: 解答の solid  （どちらも Map<"c,r", shape>）
function shapeScore(A, B) {
  const keys = new Set([...A.keys(), ...B.keys()]);
  let inter = 0;
  for (const k of keys) {
    const a = A.get(k), b = B.get(k);
    if (!a || !b) continue;
    if (a === b) inter += 1;            // 形状まで一致
    else if (a === 'F' || b === 'F') inter += 0.5;  // 全塗り↔三角 は半分だけ加点
    // 三角どうしで向きが違う場合は 0
  }
  const union = keys.size;
  return union === 0 ? 1 : inter / union;   // Jaccard 係数
}
```

**Jaccard 係数（`|A∩B| / |A∪B|`）を使う理由**: 「塗り忘れ」と「塗りすぎ」の両方を対称に評価でき、
セル数の多い問題でも 0〜1 に正規化されるため、問題間で得点の意味が揃う。

### 5.3 ハッチスコア

```javascript
function hatchScore(Ah, Bh) {          // どちらも Set<"c,r">
  const inter = [...Ah].filter(k => Bh.has(k)).length;
  const union = new Set([...Ah, ...Bh]).size;
  return union === 0 ? 1 : inter / union;
}
```

### 5.4 誤答の分類とフィードバック

`traps` による個別判定に加え、汎用の判定も行う。

| 判定条件 | タグ | フィードバック |
|---|---|---|
| 正解の `hatch` に含まれないが `solid` には含まれるセルを塗っている | `rib-hatched` | リブ・アーム・軸などは長手方向に切断してもハッチングしません |
| 正解で `solid` なのに塗っていないセルが 20% 超 | `shape-missing` | 切り口の形が足りません。切断面が通る部分をもう一度確認しましょう |
| 正解で空なのに塗っているセルがある | `shape-extra` | 材料のない部分（穴・溝）を塗っています |
| `solid` は正しいが `hatch` が空 | `no-hatch` | 切り口にはハッチングを施します |
| `hatch` が `solid` からはみ出している | `hatch-outside` | ハッチングは切り口の内側だけに施します |
| 正解にない `hidden` 線を描いている（線モード時） | `hidden-line-drawn` | 断面図では、かくれ線は原則として省略します |

`errorTags` は `results` シートに記録し、[F-32 誤答パターン集計](02_要件定義.md#23-成績分析教員)で使う。

### 5.5 採点結果の返却形式

```jsonc
{
  "score": 78,
  "passed": false,
  "detail": {
    "shape": 0.95,
    "hatch": 0.71,
    "penalty": 20
  },
  "diff": {
    "missing":     [[3,5],[3,6]],     // 塗るべきだったセル → 青で表示
    "extra":       [[4,14]],          // 余分に塗ったセル   → 赤で表示
    "hatchWrong":  [[2,10],[2,11]]    // ハッチング違い     → 橙で表示
  },

    { "tag": "rib-hatched", "message": "リブは長手方向に切断してもハッチングしません（JIS B 0001）。" }
  ]
}
```

## 6. サンプル問題（参考問題 (a) 相当）

実データ: [`samples/problem_a_full_section.json`](samples/problem_a_full_section.json)

L 字型ブラケット（縦板 ＋ 底板 ＋ 補強リブ）を、中心を通る鉛直面 A-A で全断面にした問題。

```
解答欄グリッド 6 × 16 の正解イメージ

col      0  1  2  3  4  5
row  0  [#][#][ ][ ][ ][ ]      # … 切り口（塗る＋ハッチングする）
     1  [#][#][ ][ ][ ][ ]      R … リブ（塗るがハッチングしない）
     2  [#][#][ ][ ][ ][ ]      ◣ … 三角セル BL（リブの 45° 斜面）
     3  [#][#][ ][ ][ ][ ]      [ ]… 空（材料なし）
     4  [ ][ ][ ][ ][ ][ ]  ←┐
     5  [ ][ ][ ][ ][ ][ ]    │ 縦板の貫通穴
     6  [ ][ ][ ][ ][ ][ ]  ←┘
     7  [#][#][ ][ ][ ][ ]
     8  [#][#][ ][ ][ ][ ]  ← 中心線（ヒント線として初期表示）
     9  [#][#][◣][ ][ ][ ]  ←┐
    10  [#][#][R][◣][ ][ ]    │ 補強リブ
    11  [#][#][R][R][◣][ ]    │ 斜辺は格子点 (2,9)→(6,13) の 45°
    12  [#][#][R][R][R][◣]  ←┘
    13  [#][#][#][#][#][#]  ←┐
    14  [#][#][#][#][#][#]    │ 底板
    15  [#][#][#][#][#][#]  ←┘

  ※ 左 2 列（col 0–1）は縦板の切り口。row 4–6 が貫通穴。
  ※ リブは塗る（solid）が hatch には含めない。ここが本問の要。
```

**この問題で問うている 3 つの判断**

1. 貫通穴の部分は**材料がない**ので塗らない（row 4–6）
2. **リブはハッチングしない**（`solid` だが `hatch` に含めない）
3. 中心線から外れた座ぐり穴は**断面に現れない**（かくれ線も省略するので描かない）

## 7. 将来拡張：線描画モード（Phase 4 以降）

セル塗り方式では扱えない出題（回転図示断面、任意角度の斜面、円弧）に備え、
`answer.lines` を使った**線描画モード**を用意する余地を残す。

- 格子点間の線分を引く／線種を選ぶ UI
- 採点は線分を `min(a,b)-max(a,b)` に正規化した集合の Jaccard 係数
- 円弧は「中心＋半径＋開始／終了角」で表現し、離散化して比較

問題 JSON に `answerMode: "cell" | "line"` を追加すれば、同じ画面で両方式を切り替えられる。
Phase 1 では `answerMode` を暗黙に `"cell"` として扱い、フィールド自体は最初からスキーマに入れておく。
