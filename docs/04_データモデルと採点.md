# 04. データモデルと採点方式

本アプリの核。**「断面図を描く」という作業をどうデータ化し、どう採点するか**を定義する。

> **解答方式は「自由線描画方式」に決定（D-1）**。
> 生徒は方眼の格子点どうしを結んで線を引き、線種（外形線・かくれ線・中心線）を選ぶ。
> ハッチングは領域（セル）を指定する。

---

## 1. 基本方針

断面図の作図で問われるのは、次の 3 つの判断である。

1. **切り口の形**（切断面がどこを通り、どこに材料があるか）
2. **見え掛かりの外形線**（切断面の向こう側に見える線）
3. **ハッチングの範囲**（どこに施し、どこに施さないか）

「線を引く」という操作をそのまま画面上に持ち込むと、①②を素直に問える一方で、
**同じ図でも表現がぶれる**という採点上の問題が生じる。これを線分の正規化で解く（§3）。

ハッチングだけは線ではなくセル指定にした。45° の線を 1 本ずつ引かせても
作画技能を問うだけで、「どこに施すか」という判断は変わらないためである。

指定したマスには **45° の線が 1 本**（マスの対角線）引かれる。隣り合うマスの線は
端点でつながるので、領域全体では方眼のピッチで等間隔に並ぶ連続した 45° のハッチングになる。
方眼紙に手で施すときの引き方と同じで、線が細かくなりすぎない。

| | 判定できること | 実装 |
|---|---|---|
| 線 | 切り口の形、見え掛かりの外形線、線種の選択 | 格子点間の線分 |
| ハッチング | 施す範囲（リブを除外できているか） | セル指定 |

## 2. 座標系

```
      x →   0    1    2    3
          ┌────┬────┬────┬────┐
 y  0  ●───●────●────●────●        格子点 (x, y): 0 ≦ x ≦ cols, 0 ≦ y ≦ rows  … 線の端点
 ↓        │    │    │    │    │
    1  ●───●────●────●────●        セル (c, r) : 0 ≦ c < cols, 0 ≦ r < rows  … ハッチングの単位
          │    │(2,1)   │    │
    2  ●───●────●────●────●        原点は左上。y は下向きが正（SVG と同じ向き）
          │    │    │    │    │
    3  ●───●────●────●────●
```

- 1 マスの画面上のサイズ（ピッチ）は `grid.pitch`（px）。解答欄は既定 26px
- 線分の端点は原則として整数だが、中心線のように格子の中間を通る線のために**小数を許容**する
  （例 `[0, 5.5]`）。ただし**採点対象の線は整数の格子点に限る**

## 3. 線分の正規化 ★核心

同じ直線でも、生徒によって引き方が違う。

```
  ケース A: (0,0) から (0,5) へ一気に引く          → 線分 1 本
  ケース B: (0,0)-(0,2), (0,2)-(0,5) と 2 回で引く → 線分 2 本
  ケース C: (0,5) から (0,0) へ逆向きに引く        → 端点の順序が逆
```

このままでは同じ図が違うデータになり、採点できない。そこで次の 2 段階で正規化する。

1. **既約な刻みへ分解する** — 線分 `(a → b)` の差分 `(dx, dy)` を最大公約数 `g` で割り、
   `g` 本の刻みに分ける。
   - `(0,0)-(0,5)` → `g = 5` → `(0,0)-(0,1), (0,1)-(0,2), … (0,4)-(0,5)`
   - `(2,9)-(6,13)` → `g = 4` → `(2,9)-(3,10), (3,10)-(4,11), (4,11)-(5,12), (5,12)-(6,13)`
2. **端点の順序をそろえる** — `x` が小さい方を先に、同じなら `y` が小さい方を先にする。

結果として、上の A・B・C はすべて同じ 5 本の集合になる。
これで**線の集合どうしの比較**という単純な計算に還元できる。

```javascript
function split(a, b) {                    // src/js_core.html
  var dx = b[0] - a[0], dy = b[1] - a[1];
  if (dx === 0 && dy === 0) return [];
  var g = gcd(dx, dy) || 1;
  var sx = dx / g, sy = dy / g, out = [];
  for (var i = 0; i < g; i++) {
    out.push([[a[0] + sx * i, a[1] + sy * i], [a[0] + sx * (i + 1), a[1] + sy * (i + 1)]]);
  }
  return out;
}
```

> 45° 以外の斜線（例 `(0,0)-(3,1)`）も同じ規則で扱える。方眼問題ではまず出てこないが、
> 制限を設けていないので将来の出題でも破綻しない。

### 線種 `kind`

| 値 | 用途 | 描画 |
|---|---|---|
| `outline` | 外形線 | 太い実線 |
| `hidden` | かくれ線 | 破線（断面図では原則使わない → 誤答判定の対象） |
| `center` | 中心線 | 細い一点鎖線 |
| `cut` | 切断線 | 一点鎖線。両端を太くし矢印を付ける（出題側でのみ使用） |

### `authoring` — 正解の作り方 ★重要

正解の線分を手で並べると、投影図との整合が崩れやすい。そこで**部品の形状をセル集合として
定義し、そこから外形線を機械的に導く**。

> **断面図は「切断面の材料」だけを描く図ではない。**
>
> 断面図には、切り口（ハッチングを施す部分）に加えて、
> **切断面より奥に見える面の輪郭**も実線で描く（[02 §5.4](02_要件定義.md#54-その他のルール)）。
>
> たとえば板を貫通穴の中心で切ると、切断面には穴の分だけ材料が無い。
> しかし穴は板を**幅方向には貫いていない**ので、穴の向こう側には板が残っており、
> その内壁が見える。したがって**板の外形線は穴の位置でも途切れない**。
>
> ```
>   正しい                     誤り（切り口だけを描いた図）
>   ┌────┐                     ┌────┐
>   │////│                     │////│
>   ├────┤ ← 穴の上面          └────┘
>   │    │ ← 穴（内壁が            ↑ 外形線が途切れてしまう
>   ├────┤    見えている）      ┌────┐
>   │////│                     │////│
>   └────┘                     └────┘
> ```

> **穴の径が変わるところにも線が要る。**
>
> 穴の途中で径が変わると、切断面より奥に見える面が「大径穴の壁」から「小径穴の壁」へ
> 切り替わる。見える面が変われば、そこには稜線＝実線が現れる。
> しかもこれは**大径穴の全直径**にわたって起きるので、段差の線は穴を横切る 1 本になる。
>
> ```
>   正しい                      誤り（材料との境だけを描いた図）
>   ┌──────────────┐            ┌──────────────┐
>   │//////////////│            │//////////////│
>   ├─────┬────────┤            ├─────┐────────┤
>   │     │////////│            │     │////////│
>   │大径 │        │            │大径 │        │  ← 段差の線が
>   │     ├────────┤            │     ├────────┤     穴を横切らない
>   │     │  小径  │            │     │  小径  │
>   └─────┴────────┘            └─────┴────────┘
> ```
>
> 各高さで「切断面より奥に最初に当たる面の奥行」を段差の手前と奥で比べると、
> 大径穴の範囲のどこでも値が変わる。だから線は全直径にわたる。

そこで 3 つのセル集合を扱う。

| | 意味 |
|---|---|
| `body` | 断面図に現れる**部品の外形**。切断面より奥に材料が残る範囲すべて |
| `voids` | そのうち**切断面では材料が無い**部分（穴・座ぐり・溝）。**面ごとに分ける** |
| `cut` | 切り口 = `body` − `voids`。ハッチングの対象 |

手順:

1. **部品の形を `tools/solid.py` の `Part` に一度だけ宣言する**（直方体・角柱・円柱・穴）。
   `body` と `voids` はそこから導かれる
2. 穴は **`part.hole(名前, 中心の x, 中心の高さ, [(名前, 奥行の開始, 奥行の終わり, 半径), …])`**
   で宣言する。面の分け方は自動で決まるので、手で分けて間違える余地がない
3. `cut = body − voids` を求める
4. **外形線 = `boundary(body)` ∪ `boundary(cut)` ∪ ⋃`boundary(穴の面ごと)`**
   - `boundary(body)` が部品の外形（穴の位置でも途切れない）
   - `boundary(cut)` が穴と材料の境（穴の縁）
   - `boundary(穴の面ごと)` が径の違う穴どうしの境（**段差の線**）
5. 抽出した辺を既約な刻みへ分解して `answer.lines` にする
6. `cut` からハッチングしないもの（リブなど）を除いて `answer.hatch` にする

**幅方向にも貫通していて外形が途切れる溝**などは、`voids` ではなく `body` から外す。
そうすれば `boundary(body)` が正しく途切れる。

### 穴の面は重なってはいけない

同じ奥行で見えている面はひとつなので、面の奥行の範囲は重なりません。
たとえば手前面の座ぐり φ5（奥行 0–1）と貫通穴 φ3（奥行 0–2）なら、
奥行 0–1 で見えているのは座ぐりの壁なので、その範囲は**座ぐりの面**に含めます。
貫通穴の面は奥行 1–2 だけです。`stepped_hole` はこの形でしか書けないようになっています。

### 投影図も同じ宣言から導く ★重要

**正面図・側面図・断面図は、同じ部品の宣言から機械的に導く。**
投影図を線分の列として手で書くと、同じ部品を 3 回描くことになり、
中心線の描き忘れ・見え掛かり線の描き漏れ・3 面の食い違いが必ず起きる。

```python
part = Part(w=12, h=12, d=8)                       # 幅 × 高さ × 奥行
part.box('底板', x=(0, 12), y=(9, 12), z=(0, 8))
part.box('柱',   x=(4, 8),  y=(0, 9),  z=(2, 6))
part.hole('柱の貫通穴 φ3',  6, 4.5, [('φ3', 2, 6, 1.5)])
part.hole('取付穴 φ2 左',   2, 10.5, [('φ2', 0, 8, 1.0)])
part.hole('取付穴 φ2 右',  10, 10.5, [('φ2', 0, 8, 1.0)])

front = part.front_view(cut_x=6)     # 正面図（切断線つき）
side  = part.side_view()             # 側面図
body, voids = part.section_at(6)     # 断面図のもと
```

導出の規則:

| 内容 | 規則 |
|---|---|
| **見える／かくれる** | 投影面の隣り合うマスで「材料がある奥行の集合」を比べ、違いが出る最も手前の奥行がどちらかの最前面と一致すれば実線、そうでなければかくれ線 |
| **中心線** | 穴と円柱から自動生成。縦横 2 本を円の外へ 0.8 マスはみ出させる |
| **側面図の外周** | 多角形として求める（リブの斜辺を階段にしないため） |
| **正面図の角柱** | 外接直方体として扱う（斜面は正面から見ると稜線にならない）。段のある断面形は段ごとに別の角柱として宣言する |
| **断面図の穴** | 切断面が通る穴だけが `voids` になる。通らない穴は断面に現れない |

この手順は `tools/problem_lib.py` に実装してあり、`tools/make_problems.py` が
各問題の部品形状を定義して呼び出す。Phase 3 の作問ツールはこれをブラウザ上で行うものになる。

## 6. 採点アルゴリズム

### 6.1 全体の流れ

```
1. 正規化    : 正解・解答の線分を Map<位置キー, 線種> に、ハッチングを Set<セルキー> に変換
2. 線スコア   : Jaccard 係数。位置が合えば 0.5、線種まで合えば 1.0
3. ハッチスコア: Jaccard 係数
4. トラップ判定: traps の各条件に当てはまるか → 減点 ＋ フィードバック
5. 総合点     : score = clamp(0, 100, 60×線 + 40×ハッチ − Σ減点)
6. 合否      : 線・ハッチとも tolerance 以上 かつ トラップ非該当
```

### 6.2 なぜ Jaccard 係数か

`J(A, B) = |A ∩ B| / |A ∪ B|`

- **引き忘れと引きすぎを対称に評価できる**（正解率だけだと余分な線が減点されない）
- 問題ごとに線の本数が違っても **0〜1 に正規化される**ので、問題間で得点の意味が揃う

### 6.3 線スコア

```javascript
union.forEach(function (k) {
  var a = A.get(k), b = B.get(k);       // A: 正解, B: 解答
  if (a && b) {
    if (a === b) inter += 1;            // 位置も線種も一致
    else         inter += 0.5;          // 位置は合っているが線種が違う
  }
});
return inter / union.size;
```

線種の取り違え（外形線を中心線で引くなど）を**半分だけ**加点するのは、
「形は読めているが線種の規則を覚えていない」状態を、形が読めていない状態と区別するため。

### 6.4 トラップ（典型誤答）

問題データ側で宣言し、採点ロジックは条件の種類だけを知る。

| `check` | 意味 | 使用例 |
|---|---|---|
| `hatch-in-cells` | 指定セルのどれかにハッチングを施している | リブ・穴にハッチング |
| `line-of-kind` | 指定した線種の線を引いている | 断面図にかくれ線 |
| `segments-present` | 指定した線分のどれかを引いている | 断面に現れない穴を描いた |
| `segments-missing` | 指定した線分のどれかを引いていない | 段付き部の段差を描き忘れた |
| `hatch-missing-cells` | 指定セルにハッチングを施していない | 切り口の塗り忘れ |

サンプル問題で定義しているもの:

| タグ | 条件 | 減点 | フィードバック |
|---|---|---|---|
| `rib-hatched` | リブのセルにハッチング | 20 | リブは長手方向に切断してもハッチングを施しません（JIS B 0001） |
| `hole-hatched` | 座ぐり・貫通穴のセルにハッチング | 15 | 座ぐりと貫通穴の部分には材料がありません |
| `hidden-line-drawn` | かくれ線を引いている | 10 | 断面図では、かくれ線は原則として省略します |
| `off-plane-hole` | 底板の取付穴を描いている | 10 | 切断線 A-A 上にない穴は、この断面には現れません |

トラップに当たらなかった場合は、汎用のフィードバックを返す
（`no-hatch` / `shape-missing` / `shape-extra` / `wrong-line-kind`）。

### 6.5 採点結果の返却形式

```jsonc
{
  "score": 71,
  "passed": false,
  "detail": { "line": 1.0, "hatch": 0.783, "penalty": 20 },
  "diff": {
    "missingLines": [ [[3,5],[3,6]] ],          // 足りない線     → 青
    "extraLines":   [ [[4,14],[5,14]] ],        // 余分な線       → 赤（点線）
    "wrongKind":    [ { "seg": [[0,0],[1,0]], "expected": "outline", "actual": "center" } ],
    "missingHatch": [ [3,5] ],                  // 塗り忘れ       → 青
    "extraHatch":   [ [2,10] ]                  // 余分な塗り     → 赤
  },
  "feedback": [ { "tag": "rib-hatched", "message": "…" } ],
  "tags": ["rib-hatched"]
}
```

`diff` は解答欄にそのまま重ねて表示する。`tags` は `results` シートに記録し、
[F-32 誤答パターン集計](02_要件定義.md#23-成績分析教員)で使う。

```
解答欄 6 × 16 の正解イメージ

 x→   0  1  2  3  4  5
 y 0 [##][##][  ][  ][  ][  ]     ## … 切り口（線を引き、ハッチングを施す）
   1 [##][##][  ][  ][  ][  ]     RR … リブ（線は引くが、ハッチングは施さない）

   4 [  ][  ][  ][  ][  ][  ]    │
   5 [  ][  ][  ][  ][  ][  ]    │ 手前面の座ぐり φ5（x=0 の 1 マス）と
   6 [  ][  ][  ][  ][  ][  ]    │ 貫通穴 φ3（x=0–2 を貫く）
   7 [  ][##][  ][  ][  ][  ]  ←┘
   8 [##][##][  ][  ][  ][  ]  ← 中心線（ヒント線として初期表示）
   9 [##][##][◣ ][  ][  ][  ]  ←┐

```

**この問題が問うている 4 つの判断**

1. 中心の貫通穴と**手前面の座ぐり**は材料がないので、その分だけ切り口が欠ける（y=3〜7 の段差）
2. **リブは切られていてもハッチングしない**。輪郭線だけを描く ★ 中核的な学習目標
3. 底板の取付穴は切断線から外れているので**この断面には現れない**
4. **かくれ線は省略する**（現れない穴を破線で描かない）

## 9. 問題データの検算（作図の誤りを防ぐ仕組み）

作図の規則を取り違えると、問題データが「もっともらしいが間違っている図」になる。
これは目で見ても気づきにくいので、`tools/test_core.js` が全問について次を機械的に検算する。
1 問でも破れればテストが落ちる。

| 検算 | 何を防ぐか |
|---|---|
| **穴のまわりが線で囲まれている** | 穴の位置で外形線が途切れる（切り口だけを描いてしまう誤り） |
| **穴の面がそれぞれ長方形になっている** | 段付き穴をひとつの面にまとめてしまう誤り。面は「奥行の範囲 × 直径」なので必ず長方形 |
| **丸い形にはすべて中心線が交わっている** | 穴・円柱の中心線の描き忘れ。正面図は縦横 2 本、側面図は横 1 本 |
| **段差の線が大径側の全直径にわたっている** | 段差の線が穴を横切っていない誤り。宣言された**半径**から直接確かめる |
| **径が変わる境目に線がある** | 面が違う穴セルどうしの境に線が無い誤り |
| **穴の面どうしが重なっていない** | 同じ奥行に 2 つの面を宣言してしまう誤り |
| **外形線 = `boundary(body)` ∪ `boundary(cut)` ∪ ⋃`boundary(穴の面)`** | 生成ツールの実装ミス。テスト側に**独立した実装**を置いて突き合わせる |
| **切り口 = `body` − `voids`** | ハッチング範囲と外形の食い違い |
| **断面図の外形は側面図にも現れる** | 投影図と答えの食い違い。片方だけ直すと落ちる<br>※ 逆向きは成り立たない。側面図には、切断面に材料が無いところで見えている稜線も現れる |
| **正解をそのまま出すと 100 点・合格** | 採点ロジックと問題データの食い違い |
| **正解ではどの誤答タグも立たない** | トラップの誤爆 |
| **ハッチングは切り口の内側だけ／穴に掛からない** | ハッチング範囲の誤り |
| **線をまとめて引いても・二度引いても同じ結果** | 正規化の退行 |

検算は「宣言どおりに線が引けているか」しか見られないので、**宣言そのものが誤っていると
素通りする**。そこで生成ツール側でも、誤った宣言を書けないようにしてある。

| 生成時の検査 | 内容 |
|---|---|
| `Part` | 部品の形は 1 か所にしか書けない。投影図を手で書く道が無い |
| `Part.hole` | 穴は「奥行の範囲と半径」でしか書けない。面の分け方は自動 |
| 奥行の重なり | 同じ奥行に 2 つの面を宣言すると生成が止まる |
| 格子点との整合 | 半径が格子に乗らない（穴の縁が半端な位置にくる）と生成が止まる |
| 面の形 | 穴の面が長方形でないと生成が止まる（段付き穴をまとめた形は弾かれる） |

また「外形線の組み立て」は、生成ツール（Python）とテスト（JavaScript）に
**同じ規則を別々に実装**して突き合わせるので、片方だけを思い込みで直しても通らない。

## 10. 将来拡張

- **セル塗りモード**（`answerMode: "cell"`）— 低学年向けに、線を引かず切り口を塗るだけの
  簡易モードを併設できる。スキーマに `answerMode` を持たせてあるので画面側の切り替えで済む
- **円弧** — 回転図示断面図などで必要になる。「中心 ＋ 半径 ＋ 開始／終了角」で保持し、
  離散化して線分と同じ土俵で比較する
- **ハッチングの角度・間隔** — 隣接部品で角度を変える規則（[02 §5.2](02_要件定義.md#52-ハッチングのルール)）を
  問うには、セル指定に「領域 ID」を持たせて領域ごとに角度を選ばせる
